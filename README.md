### クラウドファンディング（銀行振込による支援受付）

決済代行や銀行APIを使わず、**振込先の提示 → 支援者が銀行から振込 → サイト上で振込報告 → 管理者が入金確認 → 月末に集計・公開** という流れで運用します。

#### 公開ページ

| ページ | パス | 内容 |
| --- | --- | --- |
| プロジェクト一覧 | `/crowdfunding` | 累計支援総額・支援者数（確定済み集計のみ） |
| プロジェクト詳細 | `/crowdfunding/[id]` | 募集目的・支援金の用途・支援方法・振込先 |
| 支援ページ（全般） | `/crowdfunding/support` | 支援の手順・振込先・振込完了フォーム |
| 支援ページ（個別） | `/crowdfunding/[id]/support` | 同上（プロジェクト指定済み） |
| 支援実績 | `/crowdfunding/results` | 月別／累計の実績、ご芳名、支援金の用途 |

#### 振込先のコピー機能

スマートフォンからの利用を想定し、2種類のコピーボタンを用意しています。

- **口座番号をコピー** … 数字のみをコピー（振込画面への貼り付け用）
- **振込先情報をコピー** … 金融機関名・支店名・支店コード・口座種別・口座番号・口座名義をまとめてコピー

`navigator.clipboard` が使えない環境では `textarea` を用いた方式に自動でフォールバックします。
特定の銀行アプリへの連携は行っていないため、どの金融機関からでも利用できます。

#### 入金確認の状態

振込報告の送信と、実際の入金確認は**別の状態**として管理します。

| 状態 | 意味 |
| --- | --- |
| `REPORTED` | 振込報告済み・入金未確認（フォーム送信直後は必ずこれ） |
| `CONFIRMED` | 管理者が通帳・ネットバンキングで入金を確認済み |
| `VOID` | 確認不要／無効（重複報告・取り消しなど） |

#### 月次集計と公開

管理画面の「月次集計」で年月を指定して確定すると、その月の**入金確認済み**の支援が集計され、
`MonthlySummary` として保存されます。同時に各プロジェクトの公開用累計が自動で再計算されます。

公開ページには次を表示します。

- 月間支援総額 / 月間支援者数（**実人数**）/ 月間支援件数（**延べ**）
- 累計支援総額 / 累計支援者数（**各月の実人数の合計＝延べ人数**と明記）
- 掲載を許可した方のご芳名（敬称略・順不同）、匿名希望は「匿名希望の皆様」とまとめて表示

「支援者数」が実人数か延べ人数かは、画面上で必ず区別して表記しています。

| 項目 | 一般公開 | 管理者 |
| --- | --- | --- |
| 氏名 | 本人が掲載を許可した場合のみ | ○ |

### 権限（ロール）

3種類の権限があります。

| 権限 | できること |
| --- | --- |
| `USER`（一般会員） | イベントの参加登録、マイページ、会員一覧の閲覧 |
| `SUPPORTER`（サポーター） | 上記＋**イベントの作成**と、**自分が作成したイベントのみ**の編集・削除 |
| `ADMIN`（管理者） | すべての管理機能 |

サポーターは `/admin` に入れますが、表示されるメニューは「ダッシュボード」と「イベント管理」だけです。
広報・クラウドファンディング・支援報告・月次集計・振込先設定・参加者管理・年表・ユーザー管理には
アクセスできません（会員の所属や権限も変更できません）。

**イベントの所有者**は `Event.createdById` に記録されます。判定は `lib/auth-guard.ts` の
`canEditEvent()` に集約されており、次の3層で検証しています。

1. `middleware.ts` … `/admin/*` の管理者専用パスをサポーターから遮断
2. 各ページ … 管理者専用ページは `requireAdmin()`、編集画面は `canEditEvent()` を再検証
3. サーバーアクション … `assertStaff()` ＋ `canEditEvent()` を更新直前に実行

権限の変更は管理画面の「ユーザー管理」から行います。自分自身の権限変更と、
管理者が0人になる変更はブロックされます。

### 会員一覧

`/members`（一覧）と `/members/[id]`（詳細）を追加しました。**ログインした会員のみ**閲覧できます。

| 項目 | 一般会員から見える | 管理者・本人 |
| --- | --- | --- |
| 氏名・所属・自己紹介・登録日 | ○ | ○ |
| 権限バッジ | ○ | ○ |
| イベント参加履歴 | ○（公開イベントのみ） | ○（非公開イベント含む） |
| メールアドレス | **×** | ○ |

一覧のクエリでは `select` にメールアドレスを含めておらず、そもそもDBから読み出しません。
詳細ページでは閲覧者が管理者または本人の場合にのみ `email` を取得します。
どちらのページも `robots: { index: false }` を設定し、検索エンジンには載りません。

### 予約公開（スケジュール公開）

広報・イベント・クラウドファンディングの3つで、**下書きを書いておき、指定した日時になったら自動で公開**できます。

| 種別 | 設定する場所 | 公開される条件 |
| --- | --- | --- |
| 広報 | 「公開する」ON ＋ 公開開始日時 | 公開ON かつ 公開開始日時 <= 現在時刻 |
| イベント | 「公開する」ON ＋ 公開開始日時 | 公開ON かつ（日時未設定 または 日時 <= 現在時刻） |
| CF | ステータスが「準備中」以外 ＋ 公開開始日時 | 準備中以外 かつ（日時未設定 または 日時 <= 現在時刻） |

公開開始日時を**空欄**にすると、保存した時点ですぐ公開されます。

**仕組み**：cron（定期実行）で公開フラグを書き換えるのではなく、
「公開開始日時が現在時刻を過ぎているか」をページ表示のたびに判定しています（`lib/visibility.ts`）。
全ページが `force-dynamic` のため、**指定時刻を過ぎた最初のアクセスから自動的に記事が現れます**。

この方式を選んだ理由：

- Vercel の無料プラン（Hobby）では cron が1日1回しか実行できず、分単位の指定ができない
- cron の実行失敗・遅延で公開されないリスクがない
- 外部サービスや追加の環境変数が不要

公開前の記事は、**管理者としてログインしていれば内容を確認できます**（「予約公開」の帯が表示されます）。
一般の閲覧者・検索エンジンには、指定時刻まで一切表示されません（詳細ページも404、メタデータも出しません）。

管理画面の一覧には、状態が3種類のバッジで表示されます。

- **下書き**（グレー）… 公開OFF／ステータス準備中
- **予約公開**（オレンジ）… 公開ONだが指定時刻がまだ先。「○月○日 ○時○分 に公開」と表示
- **公開中**（緑）… 一般に表示されている

## ローカル環境の構築

前提：Node.js 20 以上、npm。

```bash
# 1. 依存パッケージのインストール
npm install

# 2. 環境変数ファイルの作成
cp .env.example .env
#    → DATABASE_URL / DIRECT_URL に Neon の接続文字列を設定
#    → AUTH_SECRET を生成して設定
npx auth secret          # または: openssl rand -base64 32

# 3. データベースにスキーマを反映
npm run db:push          # 開発中はこちらが手軽
# 履歴を残したい場合は
npm run db:migrate

# 4. サンプルデータの投入
npm run db:seed

# 5. 開発サーバーの起動
npm run dev
# → http://localhost:3000
```

## データベース設計

| モデル | 役割 | 主なリレーション |
| --- | --- | --- |
| `User` | 会員。`role` は `USER` / `ADMIN` | `EventAttendance[]`, `News[]`(著者) |
| `News` | 広報記事。`published` / `publishedAt` で公開制御 | `User`(著者, `SetNull`) |
| `Project` | クラウドファンディング案件。`status` で公開制御 | — |
| `Event` | イベント。`capacity`, `deadline` で受付を制御 | `EventAttendance[]`(`Cascade`) |
| `EventAttendance` | 参加/不参加。`@@unique([eventId, userId])` で1人1件 | `Event`, `User`（ともに `Cascade`） |
| `TimelineEntry` | 年表。`year` / `month` で並び替え | — |

`EventAttendance` に複合ユニーク制約を張っているため、参加登録は `upsert` で
「登録」と「変更」を同じ操作として扱えます。

## 権限とアクセス制御

3層で検証しています（いずれか1つが破られても防げる設計）。

1. **middleware（`middleware.ts` + `auth.config.ts`）**
   - `/mypage`, `/admin` 配下は未ログインならログインページへリダイレクト（元URLを `callbackUrl` で保持）
   - `/admin` 配下は `role !== 'ADMIN'` ならマイページへリダイレクト
   - ログイン済みで `/login`, `/register` に来た場合はマイページへ
2. **ページ側（`app/admin/layout.tsx` の `requireAdmin()`）**
   - middleware をすり抜けた場合でもサーバー側で再検証
3. **Server Action / Route Handler 側（`assertAdmin()`）**
   - フォームは直接 POST できるため、**更新処理の直前で必ず権限を確認**
   - `/api/**` は middleware の matcher 対象外なので、Route Handler 内で自前チェック

## セキュリティ上の設計

- **パスワード**：bcrypt（cost 10）でハッシュ化して保存。平文・可逆暗号は使用していません。
  ログイン時はユーザーが存在しない場合もダミーハッシュと比較し、応答時間からアカウントの
  存在有無が推測されないようにしています。
- **セッション**：JWT を HttpOnly / Secure / SameSite=Lax な Cookie に保存（Auth.js の既定）。
  CSRF 対策は Auth.js と Next.js Server Actions の仕組みに準拠しています。
- **XSS**：`dangerouslySetInnerHTML` を一切使用していません。本文は
  `components/common/article-body.tsx` で段落に分割し、React のテキストノードとして描画します。
- **SQLインジェクション**：Prisma のクエリビルダのみを使用し、生SQLは書いていません。
- **オープンリダイレクト**：`callbackUrl` は `/` 始まり かつ `//` 始まりでないものだけを許可。
- **権限昇格**：会員登録フォームの `role` は受け付けず、サーバー側で `USER` を固定。
  自分自身の権限変更・削除は不可。管理者が0人になる操作もブロック。
- **CSVインジェクション**：`=`, `+`, `-`, `@` で始まるセルは先頭に `'` を付与して無害化。
- **入力検証**：すべてのフォームは Zod スキーマでサーバー側検証を行います。
  HTML の `required` などはあくまで補助であり、信頼していません。
- **管理画面の noindex**：`/admin` と `/mypage` は `robots: { index: false }` を設定。

## 実装していない機能と代替案

正直に書いておきます。以下は**本アプリの範囲外**としました。

| 機能 | 実装しなかった理由 | 代替案 |
| --- | --- | --- |
| オンライン決済（カード決済） | 学生団体が自前で決済を扱うのは、特定商取引法・資金決済法・PCI DSS の観点で負担が大きすぎます | **銀行振込**で受け付け、サイト上では振込先の提示と振込報告のみを行う。カード情報等は一切お預かりしません |
| 銀行API連携・入金の自動照合 | 個人・小規模団体が利用できる入出金APIは限られ、契約と維持費が必要です | 管理者が通帳・ネットバンキングを確認し、管理画面で「入金確認済み」に変更する運用 |
| 画像アップロード | Vercel のファイルシステムは書き込み不可（読み取り専用）のため、サーバーに直接保存できません | 現状は**画像URLを入力**する方式。自前アップロードが必要なら Vercel Blob / Cloudinary / S3 を導入し、`coverImage` にURLを保存してください |
| メール送信（登録確認・パスワード再設定） | SMTP または Resend / SendGrid などの外部サービスと APIキーが必要で、環境依存になります | Resend + Auth.js の Email Provider、またはパスワード再設定は管理者による手動対応 |
| リッチテキストエディタ | Markdown/HTML を受け付けるとサニタイズが必須になり、XSSリスクが増えます | プレーンテキスト＋空行での段落分割。必要なら `react-markdown` + `rehype-sanitize` を追加してください |
| 全文検索 | PostgreSQL の全文検索は日本語形態素解析の設定が別途必要です | ユーザー管理のみ `contains` による部分一致検索を実装。本格的な検索は Meilisearch / Algolia を検討 |
| 支援額の自動同期 | 外部CFサービスの公開APIが保証されていません | 管理画面からの手動更新 |
| 会員名簿の公開 | 個人情報保護の観点から公開しない設計にしています | 管理画面でのみ閲覧可能 |
